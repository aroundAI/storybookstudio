# StorybookStudio Capability Matrix

This maps every MCP tool the upstream editor defines in `electron/mcpServer.js` (`createToolDefinitions()`) onto the verbs of [AI_EDITOR_CONTRACT.md](AI_EDITOR_CONTRACT.md). The intent compilers (FILM-2013) build their action plans from the tools marked `exists` or `adapter`. A `build` item is something the contract needs that no upstream tool provides, with the spec that builds it.

## Classes

- **exists**: usable as is. For a tool with a contract verb, an intent compiler or capability tool can call it unchanged. For a tool with no verb (generation, ComfyUI, Music Video, stock), it stays in the `expert` profile unchanged and nothing needs building.
- **adapter**: usable with a thin wrapper or a small change. The note says which, and which spec makes it.
- **build**: missing. Listed in the second table, since no upstream tool exists to classify.

## Columns

- **Contract verbs**: clause ids from the contract (P perception, E editing primitives, V validation, L lifecycle).
- **previewOnly**: `yes` when the input schema accepts `previewOnly`; `yes, default` when the tool or property description says it defaults to preview.
- **In plans**: whether `run_mcp_action_plan` accepts the tool as a step (`MCP_ACTION_PLAN_WRITABLE_TOOLS`).
- **What it does**: the first sentence of the tool's own description.

## Regenerating

The block below is generated. Names, descriptions and schemas come from evaluating `createToolDefinitions()`. Group, verbs, class and notes are hand-filled in `scripts/capability-matrix.classes.json`.

```bash
node scripts/capability-matrix.mjs           # print the counts
node scripts/capability-matrix.mjs --write   # rewrite the block below
node scripts/capability-matrix.mjs --check   # fail if a tool is unclassified or this file is stale
```

After an upstream merge adds or removes a tool, `--check` fails (and so does `tests/studio/capabilityMatrix.test.mjs`) until the tool is classified in the JSON and the block is rewritten.
